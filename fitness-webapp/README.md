# Fitness platform — реальный проект (этап 1)

Настоящее React-приложение (Vite), подключённое к вашей базе Supabase.
На этом этапе работает: выбор тарифа, регистрация/вход клиента по email и
паролю, вход тренера, оплата-заглушка, анкета онбординга, список клиентов
у тренера. Тренировки, питание, чек-ины, прогресс и чат подключим следующими
шагами — они пока есть только в Claude-прототипе (`fitness-platform.jsx`).

## Запуск локально

```bash
npm install
cp .env.example .env
npm run dev
```

Откроется на `http://localhost:5173`. `.env` уже содержит ваши настоящие
`VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` — можно сразу пробовать
регистрацию клиента и вход.

### Как создать первого тренера для входа

Публичной регистрации тренеров нет специально. Чтобы Виктория или Александр
могли войти:

1. В Supabase → **Authentication → Users → Add user** — создайте пользователя
   с их email и паролем (можно поставить галку "Auto Confirm User").
2. В **Table Editor → trainers** — откройте строку с `id = 't1'` (Виктория)
   или `'t2'` (Александр) и впишите в поле `auth_user_id` UUID только что
   созданного пользователя (скопируйте его со страницы Authentication → Users).
3. Теперь этим email/паролём можно войти на экране «Я тренер».

## Деплой на Vercel

1. Запушьте эту папку в отдельный репозиторий на GitHub (так же, как делали
   с прокси-серверами — `git init`, `git add .`, `git commit`, `git push`).
2. На **vercel.com** → **Add New → Project** → выберите репозиторий.
3. Vercel сам определит, что это Vite-проект.
4. В **Environment Variables** добавьте `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` (значения — как в вашем `.env`).
5. **Deploy** — через минуту получите настоящий рабочий адрес вида
   `https://fitness-platform.vercel.app`.

## Что дальше

Следующими шагами перенесём в базу и в это приложение:
- тренировки и режим их проведения,
- дневник питания (с поиском продуктов через уже готовый `openfoodfacts-proxy`),
- еженедельные чек-ины с фото,
- прогресс и аналитику «на что влиять»,
- чат поддержки для VIP.

Каждый шаг — отдельная порция изменений, чтобы не сломать то, что уже
работает.
